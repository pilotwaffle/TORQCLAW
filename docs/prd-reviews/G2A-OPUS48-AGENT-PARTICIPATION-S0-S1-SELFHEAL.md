## 1. S1 agent identity (`7ac78fb`) — APPROVE

- **(a) Admits ONLY `POST_CHANNEL_MESSAGE`:** confirmed at `authz.ts:172-174` — a single exact-match branch inside the `node` arm, everything else falls to `DENY_NOT_PERMITTED`. Unit-pinned including non-widening of `SUBMIT_PROMPT`/`APPROVE_TOOL` (`agent-participation-s1-authz.test.ts:80-85`).
- **(b) `agentCollabWrite` is NOT client-influencable — verified by full trace.** `server.ts` computes it as `agentCollabPrincipalId !== null && agentParticipationEnabled()`. The principal id is set once at CONNECT from `caller.binding!.principalId`, only when `isAgentSurfaceCaller(caller.authClass, caller.binding)`. Both inputs come from `resolveConnectIdentity` over a cryptographically verified `tq1_` credential. `ConnectFrameSchema` carries **no** `principalId`/`authClass`/`principalKind` field at all — there is nothing on the wire for a client to influence. The flag is re-read live per call (mid-connection flip takes effect next command) — correct discipline.
- **(c) `authClass` vs DB kind:** the builder's removal of the redundant `getPrincipalKind` re-check is justified. `authClass` is derived from the same verified `principalAuthorityForPrincipal` lookup in the same synchronous connect path (`collabIdentity.ts:515-523` and `:549-558`); a second read of the same handle microseconds later cannot disagree. Mutation-proven by the builder; reasoning holds on my read.
- **(d) `automation_surface` excluded:** yes — the C1 branch assigns `automation_surface` exactly when `surfaceRole === 'automation'`, and `isAgentSurfaceCaller` requires exactly `'agent_surface'`. Pinned at the extracted-predicate level (`:28-34` of the authz test). The builder's disclosure that this is predicate-level only, not live-wire, is accurate — no test provisions a C1 automation surface end-to-end. Acceptable given provisioning that fixture requires pre-boot C1 rows in both DBs; recorded as residual risk, not a defect.
- **My falsifiability probe (worktree, rebuilt artifact):** removed the `agentCollabPrincipalId ??` fallback from the POST dispatch arm → **3 RED with `COLLAB_IDENTITY_REQUIRED`** (A1-a, A1-b, A1-e), matching the commit message's recorded output. Restored, rebuilt, 9/9 green.

## 2. Operator C1 self-heal (`12ea0fc` + fix in `9b544ee`) — APPROVE, after one real defect

- **Principal synthesis? NO — verified, not argued.** The heal runs only inside `if (legacy !== null)` after `verifyLegacySurfaceAuthority` → `verifyCredential` (HMAC recompute + `safeCompare32`, `credentials.ts`) succeeds, and only under `legacy.principalKind === 'operator'` (a DB read of the verified credential's own principal row, `collabIdentity.ts:537`). Three independent barriers against non-operator provisioning, including the schema's `principals_single_operator` unique index. No unverified caller can reach it; no client-frame field feeds it.
- **No-new-secret claim: TRUE.** The INSERT binds the existing `principal_credentials.id` and copies the stored `secret_hmac` bytes verbatim; no token minted, nothing re-derived, logged, or returned. The single `randomUUID()` is the non-secret `surface_id`.
- **The disclosed race is safe for the disclosed reason, verified:** the loser's `tx()` hits `UNIQUE` on `surface_credentials.credential_id` (PK) / `secret_hmac` (unique) and rolls back **both** collab inserts atomically. No half-write from concurrency.
- **B-SH-1 (the real defect): the race disclosure missed the un-transacted cross-DB write.** I found this by source read before seeing G1R's verdict: `activateSurfaceProjection(stateDb, …)` runs *outside* and *after* the collab transaction; a failure in that window leaves collab.db provisioned and state.db empty, the original `already` guard then early-returned forever, and `validatePresentingSurface` denies on the missing projection (`surfaceGate.ts:108-109`) — a permanent brick with a misleading `selfHealed: true` audit row, indistinguishable from the pre-fix bug. G1R reproduced it empirically twice. **The fix in `9b544ee` is correct** (JOIN over both collab tables + projection existence check + idempotent re-activation, same-role so no epoch bump), and **I proved the pin**: reverting the guard to the naive form in the worktree, rebuilding, and running the suite turned the new B-SH-1 regression test RED — `COLLAB_IDENTITY_REQUIRED` on the real booted gateway, exactly the brick. Restored, rebuilt, 4/4 green.
- **`allowedCapabilityClasses` — RULING: `[]` is correct, and it is what shipped in `9b544ee`.** I endorse G1R's reasoning independently: the "preserving prior authority" justification was wrong on the facts (there was no surface row — nothing to preserve); the field is stored/projected but consulted by no gate today (grep-verified across `packages/gateway/src`); and the reversible direction is narrow — widening later is a one-line reviewed change, narrowing after installs accumulate `exec`-bearing rows is not. **Suggestion (non-blocking):** add a grep-guard test pinning that nothing in `packages/gateway/src` reads `allowedCapabilityClasses` as a gate yet, so the day enforcement lands it must be declared — the auth-v2-phase1 SHA pin is the house pattern for exactly this.

The gap (no way to distinguish "legacy human-paced, no grant by design" from "unattended run whose grant is missing") is real, open, and precisely TODO'd; no unattended caller exists today, so no current caller can reach the weak arm with a grant-bearing re-run. ## 4. The SecretStore commit (`9b544ee`) — APPROVE

- **FileSecretStore:** atomic create (`openSync(tmp, 'wx', 0o600)`), same-dir temp + rename, pre-rename exists re-check, `set()` throws on existing (never silently rotates a live pepper), honest Windows threat-model statement (mode bits advisory under NTFS; file/env tier, not keyring tier). The residual TOCTOU between the pre-rename check and `renameSync` is narrower than before and honestly documented; on Windows `renameSync` onto an existing file throws — fails safe.
- **bootstrap.ts compensating rollback:** the two `set()` calls after a committed DB tx now roll back exactly the four self-inserted rows, zero the buffers, and throw `BootstrapSecretPersistError`; the orphaned-pepper-file residual is documented with the correct reasoning (inert, no DB row references it, retry mints fresh non-colliding material). Sound.
- **The headline claim is true and was load-bearing:** production previously wired the throwing `WindowsCredentialManagerStore` stub, so no real credential could ever authenticate — the entire collab feature was inert in production and every green boot test substituted an in-memory store via preload. The recorded standing rule ("a test that boots the real artifact must state which production dependencies its harness substitutes") is the correct generalization of the lesson this program has now learned at three depths.

## 5. Interaction scenarios (the brief's combinations) — all traced, none combine badly

- **Agent × self-heal:** unreachable — the heal is gated on `principalKind === 'operator'`; an agent legacy credential never enters it. S1's agent path stays on C0.1 by design.
- **Self-healed operator × approval path:** the heal makes `connectionAuth` non-null, which lets `recordTaskOrigin` run, which gives C2 registration its evidence, which lets S0's now-ungated producers mint bindings/grants — **the LOCAL_EDGE fence engages for the operator's approvals**. That is the intended tightening, and flag-off remains byte-identical because `validatePresentingSurface` no-ops flag-off (surfaceGate.ts:92), so no heal, no evidence, no fence.
- **`agentCollabPrincipalId` vs `connectionAuth.principalId` disagreement:** impossible by construction — both derive from the same verified credential in the same synchronous connect path; when both are non-null they are the same principal, and the POST arm's precedence matches the authz gate that admitted the connection.
- **Self-heal creating the evidence S0 keys on:** real and coherent, as above. The one residual worth naming: with the flag ON, every operator connect now provisions a C1 surface, so "legacy human-paced operator with no grant by design" becomes a shrinking population — which strengthens, not weakens, the case for C-1's unattended-marker TODO when cron lands.
